== What is Red Hat Ansible Automation Platform?

Red Hat Ansible Automation Platform is an end-to-end automation platform for configuring systems, deploying software, and orchestrating advanced workflows. It includes the tools and resources necessary to create, manage, and scale automation across the entire enterprise.

Thousands of organizations worldwide use Red Hat Ansible Automation Platform to automate their IT infrastructure. Whether you need to deploy applications, configure servers, manage network devices, or orchestrate cloud resources, Red Hat Ansible Automation Platform provides a consistent automation framework.

The platform includes components like ansible-playbook for running automation tasks, ansible-navigator for content execution, and Automation Controller for enterprise-scale orchestration. All of these components share one thing in common: they use YAML as their content language.

== What is YAML?

YAML stands for *YAML Ain't Markup Language*. It is a human-readable data serialization language designed to be easy for people to read and write while remaining simple for machines to parse.

Let's compare the same data structure in three different formats to see why YAML stands out.

*XML format:*
[source,xml]
----
<server>
  <name>webserver</name>
  <port>80</port>
  <enabled>true</enabled>
</server>
----

*JSON format:*
[source,json]
----
{
  "server": {
    "name": "webserver",
    "port": 80,
    "enabled": true
  }
}
----

*YAML format:*
[source,yaml]
----
server:
  name: webserver
  port: 80
  enabled: true
----

Notice how the YAML version has minimal punctuation and reads almost like structured English. There are no brackets, braces, or closing tags to manage. The structure is defined entirely by indentation, making it clean and easy to scan.

== Why Red Hat Ansible Automation Platform uses YAML

Red Hat Ansible Automation Platform uses YAML because it offers a straightforward, human-readable way to write automation content. Ansible Playbooks must be both human-readable for collaboration and machine-parseable for automation. YAML satisfies both requirements.

Consider this simple Ansible Playbook written in YAML:

[source,yaml]
----
---
- name: Install and start Apache web server
  hosts: webservers
  become: true
  tasks:
    - name: Install Apache package
      ansible.builtin.package:
        name: httpd
        state: present

    - name: Start Apache service
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true
----

Even if you have never seen an Ansible Playbook before, you can understand what this automation does. It installs the Apache package and starts the Apache service on servers in the `webservers` group. The YAML syntax does not get in the way of understanding the automation logic.

This readability is critical for teams. Automation content is written once but read many times — by different team members, during code reviews, during troubleshooting, and during updates. YAML makes all of these activities easier.

== YAML advantages: readability and simplicity

YAML offers several advantages that make it ideal for automation content:

*Simplicity:* YAML has minimal syntax compared to JSON or XML. You do not need to remember when to use brackets, braces, quotes, or closing tags. Indentation and structure tell the whole story.

*Readability:* YAML looks like structured English prose. Lists, dictionaries, and values are represented in a way that feels natural to read. You can scan a YAML file quickly and understand its structure without parsing complex syntax.

*Ease of learning:* Beginners can read and write YAML quickly. The learning curve is gentle, which makes automation accessible to broader teams — not just developers, but system administrators, network engineers, and anyone responsible for managing infrastructure.

*Version control friendly:* YAML's line-based structure works well with version control systems like Git. Changes are easy to track in diffs, and merge conflicts are easier to resolve because each key-value pair typically occupies its own line.

These advantages make YAML the perfect fit for Red Hat Ansible Automation Platform. Understanding YAML is the first step to automation success with the platform.
